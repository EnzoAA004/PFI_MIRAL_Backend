## 4. AI models — detail

### 4.1 Sagittal segmentation (SPIDER U-Net2D)
- **Objective**: academic-support multiclass segmentation of sagittal lumbar MRI; explicitly "no produce diagnostico automatico" (modelcard, verbatim).
- **Input**: 1×256×256 tensor. **Output**: 4 classes — background, vertebra_group, canal, disc_group.
- **Architecture**: `SagittalUNet2D`, base_channels=16.
- **Dataset**: SPIDER sagittal lumbar MRI; patient split train=152/val=33/test=33 (slices 5271/1174/1218).
- **Training**: `notebooks/45_gcs_spider_final_training.ipynb`, AdamW, weighted CE+Dice, early stopping patience 12, 75 epochs, best epoch 63.
- **Metrics**: val Dice macro (no bg) **0.8993**; test Dice macro **0.8934**; test IoU macro **0.8080**; threshold 0.70; quality gate **approved**.
- **Checkpoint**: in git, `models/final/sagittal_spider_multiclass_final_best.pt` (~1.98MB).
- **Limitations** (verbatim, modelcard): no clinical validation; may be biased to the SPIDER domain evaluated; requires human professional review; must not be used for automatic diagnosis.

### 4.2 Axial segmentation (Sudirman/Al-Kafri U-Net2D)
- **Objective**: academic multiclass axial lumbar MRI segmentation.
- **Input**: `AxialUNet2D`, target 256×256. **Output**: 6 classes (background_250, raw_0/50/100/150/200).
- **Dataset**: ALKAFRI/Sudirman axial T2 lumbar MRI.
- **Training**: best epoch 17, monitor `dice_macro_foreground`, best val metric 0.7283.
- **Metrics**: val dice_macro_foreground **0.7283** (excl. raw_0: 0.8772); test dice_macro_foreground **0.6793** (IoU 0.5700, excl. raw_0: 0.8106). `raw_0` class weak (test dice 0.1545, precision 0.0864).
- **Quality gate: `qualityGatePassed: false`** (`dice_macro_foreground_below_threshold`).
- **Held-out caveat** (verbatim): the test partition was previously evaluated for a prior baseline — "this v2 evaluation is comparative and should not be interpreted as a fully untouched external validation."
- **Checkpoint**: in git, `models/final/axial_t2_alkafri_final_v2_candidate.pt` (~1.98MB).

### 4.3 67B2 — absolute lumbar level localization
- Abstention-capable localizer; states `localized`/`abstained`/`unavailable`.
- Runtime status (code, verbatim keys): `artifactAvailable=false, runtimeAvailable=true, productEnabled=false, validated=true, abstentionSupported=true, parityVerified=false, adapterStatus="parity_not_proven"`.
- Frozen-freeze classification: `VALIDATED_WITH_ABSTENTION`, model SHA `bb9e9d81…`.
- **Offline metrics verified in the 67B2 notebook**: DEV top1 `0.9343629343629344`, top2 `0.972972972972973`, MRR `0.9617117117117117`, `n=259`; locked validation raw Top-1 `0.9049295774647887`, raw Top-2 `0.9612676056338029`, raw MRR `0.9448356807511736`; pipeline accuracy given emit `0.9909502262443439`.
- Runtime/product availability remains blocked: `67B2_RUNTIME_PARITY_NOT_PROVEN`, `productEnabled=false`, `parityVerified=false`. Fail-closed by design — never fabricates a level without a proven runtime-parity artifact.

### 4.4 67C — sagittal→axial geometry pairing
- Deterministic geometric algorithm (not a trained model): `BASELINE_A_NEAREST_PLANE_PLUS_FOV`, pairs a sagittal disc centroid to the nearest valid axial DICOM slice.
- Params: `min_margin≈0.2616`, `max_plane_distance≈23.818`, `require_inside_fov=true`.
- Status: `validated=false, experimental=true, reviewRequired=true, parityVerified=false, productEnabled=false`.
- Blocked reason: `67C_RUNTIME_PARITY_NOT_PROVEN`; only runs downstream of a localized 67B2 level (which is itself always blocked, §4.3).

### 4.5 P10.7 — degenerative findings
- **Subarticular classifier**: EfficientNet-B0, 3-class (normal_mild/moderate/severe) per level/side, 2.5D ROI input. Internal test metrics (n=2876, verbatim): macro_f1 **0.6285**, balanced_accuracy **0.6565**, normal_mild_recall 0.8455, moderate_recall 0.4458, severe_recall 0.6782, weighted_log_loss 0.6885. Checkpoint external to git, SHA-pinned, gated by `PFI_SUBARTICULAR_CHECKPOINT_PATH`.
- **Disc-multitask classifier**: 8 findings per disc level (pfirrmann_grade, modic_change, endplate changes, spondylolisthesis, disc_herniation, disc_narrowing, disc_bulging). Checkpoint external, SHA `16eccff3…`.
- **Blocked**: `POST /degenerative-findings/disc-multitask/predict` → `422 DISC_DEGENERATIVE_PREPROCESSING_NOT_AVAILABLE` because `AUTOMATIC_DISC_LOCALIZATION_VALIDATED=false` and `REAL_RUNTIME_PREPROCESSING_PARITY_VALIDATED=false` (doc, verbatim).
- Deployment tiers (doc, verbatim): supported_internal = upper/lower_endplate_change, disc_narrowing, disc_bulging; experimental = pfirrmann_grade; not_product_supported = modic_change, spondylolisthesis, disc_herniation.

### 4.6 Grad-CAM explainability
- Applies only to the subarticular classifier, hooked at `backbone.bn2`.
- Output: 224×224 heatmap, normalized [0,1], plus metadata (`modelId, modelVersion, task, targetClass, layer, method=gradcam, layerDisclaimer`).
- Tests: AI-specific Grad-CAM tests PASS against the real checkpoint when present; API contract validated; Frontend wiring present. **Not exercised explicitly in the final 11/11 browser E2E path**.
- Limitation (verbatim): "explains only the visual (backbone) branch — the side/level embeddings are not represented"; "never a diagnosis, never a severity signal."

## 5. User/professional workflow (as implemented)

```
Study created (subjectRef identity, not yet the Patient entity — see §3)
  → DICOM/series ingested (upload or server-side fixture)
  → AI multiplanar run (sagittal always; axial optional)
  → measurements + segmentation overlays returned
  → professional reviews: accepts/corrects measurements, edits evidence regions
  → structured report assembled (+ optional Grad-CAM explanation, optional chat)
  → export: PDF / JSON
  → history: subject timeline across Studies
  → longitudinal comparison: two Studies of the same subject (demo path only for a
    resolved anatomical level, see §6)
```

**Explicit non-negotiables enforced end-to-end** (governance flags, verified live this session):
`humanReviewRequired=true` and `notClinicalDiagnosis=true` on every AI response;
`autonomousDiagnosis=false`; professional review is mandatory before a finding is presented as
accepted; the product is a **non-diagnostic decision-support tool**, never an autonomous
diagnosis/treatment system.

## 6. Demo Mode

- **Purpose**: a fully deterministic, non-clinical path that lets the whole product (patients,
  studies, AI run, measurements, longitudinal trend, report, chat) work end-to-end without a
  validated anatomical localizer, which the real path (§4.3–4.5) intentionally refuses to fabricate.
- **Fixture**: `fixture:sagittal_sample`, a single-slice 2D `.npy`, registered via
  `POST /api/ai/inputs/server-side`.
- **Scale**: 4 studies (`DEMO-LUMBAR-2026-01/02/03`, `DEMO-LUMBAR-ALT-01`), 2 subjects
  (`DEMO-PAT-001`, `DEMO-PAT-002`).
- **Localization label**: `localizationStatus="demo_fixture"`, `source="DEMO_FIXTURE"`,
  `validated=false`, warning `DEMO_FIXTURE_LOCALIZATION_NOT_REAL_INFERENCE` always present —
  engages **only** when the caller opts in via `metadata.mode=="demo"` and the real 67B2 pipeline
  could not localize; never overrides a genuine localized/abstained result.
- **Longitudinal demo values**: deterministic per caseId — 11.9 / 12.3 / 13.1 mm, with a
  professional correction to 12.9 mm on the third study (delta 0.6mm, `comparisonStatus=comparable`).
- **Report/chat flow**: same code path as the real product (`pfi.study-report.v1` schema, same PDF
  renderer, same chat service against the configured LLM provider/mock).
- **Playwright**: 11/11 PASS, run twice against `main` this session (reconciliation branch stack,
  then the final `main`-only stack).
- **Never conflate with real inference**: overall `product-analysis.status` is forced to
  `"partial"` (never `"completed"`) whenever demo data is used, specifically so it cannot be
  mistaken for a completed real analysis.

## 7. Consolidated limitations

1. **67C experimental** — `experimental=true`, `validated=false` always; geometric pairing only, not a trained/validated model.
2. **67B2 parity/runtime constraints** — `parityVerified=false`; no artifact demonstrates parity against the frozen freeze; fails closed, never fabricates a level.
3. **P10.7 preprocessing parity** — blocked because automatic disc localization and real-runtime preprocessing parity are both unvalidated; checkpoints external to git, SHA-pinned.
4. **Grad-CAM experimental** — visual-branch only; not exercised as a full 3-tier Docker E2E.
5. **AI asset/slice registry ephemeral (P2)** — reproduced twice more this session (reconciliation stack + final main stack): restarting the AI container invalidates prior runs' registered inputs/assets until re-registered; workaround (re-register + re-run) confirmed working every time.
6. **Validation sample limitations** — sagittal model: 218 patients total across train/val/test; axial model's held-out test partition reused from a prior baseline evaluation (own modelcard caveat); subarticular classifier internal-test only (n=2876), no external validation found in repo.
7. **No clinical diagnosis claim** — `notClinicalDiagnosis=true` and `humanReviewRequired=true` are structural invariants across every AI response in both real and demo paths; the product is decision support only.
8. **Cloud AI real deployment not completed** — AI Cloud Run service module exists in Terraform but is explicitly disabled (`enable_ai_service` flag off); the private-AI Google ID Token auth path has never been exercised against a live Cloud Run AI service.
9. **Cost/performance cloud measurement pending** — no Cloud Run cost or latency measurement found in repo for a live deployment; DEV Cloud Run smoke tests exist (§8) but no sustained load/cost data.
10. **Patient domain — IMPLEMENTED_PARTIAL (new finding, this audit)** — `/api/patients`, `Study.patientId`, Patient↔Study association and persistence exist and are tested on Backend `main`, but the Frontend does not fully consume the Patient entity domain; the shipped product's real identity/history/longitudinal flow is `subjectRef`-based end-to-end. **Do not describe Patient-entity association as a browser-level end-to-end feature.**
11. **Demo Mode has no persistent UI indicator (new finding, this audit)** — no grep hit for a "Demo" badge/banner in `Header.tsx`, `AppShell.tsx`, `StatusBadge.tsx`, or `PrivacyBanner.tsx`; demo-vs-real is an internal data-mode flag (`src/dataMode.ts`), surfaced to the user only incidentally in toast/fallback text.
12. **enforcer/spotless not adopted (P3)** — main's `maven-enforcer-plugin` (hardcoded Java `[17,18)` range) and `spotless-maven-plugin` (auto-reformat) were deliberately not carried into the reconciled `pom.xml`; left for a focused follow-up.
